# proofbox grants itself macOS screen and input access on each Mac

A command over `nsc ssh` runs outside the desktop session and has no screen or input permission, and macOS 26 also shows a "bypass the system private window picker" alert that waits for a click. On every Mac, proofbox therefore:

- runs desktop commands in the user's session (`sudo launchctl asuser 501 sudo -u runner …`),
- grants `kTCCServiceScreenCapture`, `kTCCServiceAccessibility`, and `kTCCServicePostEvent` to `/usr/libexec/sshd-session`, `/usr/libexec/sshd-keygen-wrapper`, and `/usr/sbin/sshd`, the programs behind the Mac's sshd that runs our commands (ADR 0022), in the system TCC database (possible because SIP is off and sudo needs no password),
- grants Apple Events from all three sshd programs to System Events, Terminal, and Finder in runner's own TCC database (`~/Library/Application Support/com.apple.TCC/TCC.db`), since this consent is per user and rows in the system database still show the dialog, so an `exec` that controls one of them does not wait on a "sshd-keygen-wrapper wants access to control" dialog that the Caller cannot see,
- writes an approval for `/usr/libexec/sshd-keygen-wrapper` in `~/Library/Group Containers/group.com.apple.replayd/ScreenCaptureApprovals.plist` before the first capture, with every date replayd itself writes, then stops replayd with `kill -9` so it reads the file again (replayd is already running at boot, keeps approvals in memory, and saves them over the file on a normal stop).

This edits private macOS files on purpose, so it can break with a macOS update. Before the test screenshot, `create` turns off display sleep, system sleep, and the runner screen saver (`pmset -a displaysleep 0 sleep 0 disksleep 0`), reads `pmset -g` back, and fails when the display can still sleep; a sleeping display gives black screenshots (#117). `create` ends with a test screenshot and a 1-second test capture and fails clearly when either is blocked or an alert is on screen. It also sends one Apple Event to System Events with a short time limit and fails clearly when that is blocked. The capture does not wait on the replayd alert, so a replayd that moved the approval's hint date also counts as an alert. Details: `docs/research/namespace-test.md`.

## Considered options

- Grant Apple Events to every app: not possible. macOS asks for Apple Events consent once per target app, and has no wildcard target. The GitHub Actions macOS images also pre-grant a fixed list ([configure-tccdb-macos.sh](https://github.com/actions/runner-images/blob/main/images/macos/scripts/build/configure-tccdb-macos.sh)). Another target app shows the dialog once, and the Caller clicks Allow while the `exec` waits.
- Grant no Apple Events and document how to click Allow, as ADR 0020 does for other dialogs: rejected. Each first `exec` that controls an app loses about 2 minutes (#120). ADR 0020 keeps the dialogs a real user of the Caller's app would see. Nobody ever sees one about `sshd-keygen-wrapper`, so skipping it hides nothing about the app, and Apple Events that the Caller's app sends still ask.
